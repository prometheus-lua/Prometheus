# VM scalar, cleanup, and call optimizations

Host: Linux-6.18.33.2-microsoft-standard-WSL2-x86_64-with-glibc2.44; CPU: 13th Gen Intel(R) Core(TM) i7-13850HX. Runtimes: Lua 5.1.5  Copyright (C) 1994-2012 Lua.org, PUC-Rio; LuaJIT 2.1.1792588164 -- Copyright (C) 2005-2026 Mike Pall. https://luajit.org/.

Four deterministic workloads compare original source with the actual presets, including AntiTamper. All variants must match the original checksum.

Seeds: [1, 4, 17]; 3 timed batches per seed. Each workload is parsed once and warmed up; batches adapt to approximately 0.1 seconds. Execution includes initialization of the emitted chunk, workload work, allocations, and checksum validation, but excludes parsing. Garbage collection runs before each batch; collection during the batch is included.

Execution figures are median CPU time per full invocation across batches and seeds. Generation and parsing figures are medians across seeds. Output size is a median across seeds. Execution ranges show the lowest and highest per-seed medians. Measurements are local, with JIT enabled for LuaJIT; very small native JIT times can produce large slowdown ratios. These workloads do not establish a general performance guarantee or measure peak memory.

## Before and after

The baseline is commit `458f897`, exported to an isolated source snapshot.
Both versions were benchmarked sequentially on the same host after correctness
checks finished. Both retained the Medium preset, including AntiTamper and
Cff-protected helpers. Each uses seeds 1, 4, and 17 with three timed batches.
Measurements are separate runs; small differences can include timing variation.
The original-source timing in each raw report helps show that variation.

The compiler now lowers fixed-length assignment values directly to registers;
all right-hand expressions still run before stores. It removes safe temporary
copies, retargets scalar producers, deduplicates clears, batches adjacent clears,
and remaps jumps within basic blocks. Calls with zero through three closed
arguments and closed returns of up to three values use native argument and
return lists. Varargs, expanding final arguments, larger argument lists, and
multi-result call capture retain counted tuple paths. Small non-vararg callees
also avoid constructing an incoming argument tuple.

Parallel assignment stores now execute right to left, matching native Lua,
including duplicate destinations and table metamethod side effects.

All benchmark checksums matched original execution. The two runs comprise 48
transformed preset/runtime combinations and 16 original executions, with 192
timed batches. The semantic suite passed 1,260 transformed runs across three
seeds and 70 baselines, with zero failures or timeouts. Targeted arity, capture,
cleanup, tail-call, and all-24-operand-layout checks passed on Lua 5.1 and LuaJIT;
browser tests and the production build passed.

The extra handlers enlarge the interpreter, while smaller instruction tables
offset that growth. Total output is slightly smaller in three workloads and
about 1 KiB larger in the numeric workload. Execution is faster in these
workloads, but the VM still has substantial overhead relative to native Lua.
This change does not alter Medium's protection strategy, opcode
randomization, operand layouts, or balanced dispatcher.
